# Реализованный дизайн

Текущая версия переработана по присланному пользователем скриншоту и уточнению:
нужен самостоятельный интерфейс LLauncher в стилистике Endfield.

## Текущее направление

- Тёмная нейтральная основа, большой игровой арт с плавным переходом к нижней полосе.
- Узкая левая панель с присланной иконкой (`src/assets/launcher-icon.png`) и ссылками сообщества.
- Баннер целиком, вкладки новостей и запуск выровнены в одном нижнем ряду. Карусель
  имеет ограниченную высоту; изображения больше не растягивают страницу.
- Названия вкладок читаются из реального поля API `tabName`. Ссылки VK и Telegram
  показывают значки сервисов. Загруженный из кеша фон не остаётся невидимым.
- Настройки полупрозрачны: затемнение 78%, размытие 18px. Арт виден через контент,
  навигацию и нижнюю панель; для второстепенного текста усилен контраст.
- Жёлтая кнопка запуска и соседнее меню: обычный запуск остаётся основным, запуск
  с модами, настройки игры и импорт находятся в меню.
- Параметры установки, путь и свободное место раскрываются над кнопкой. При нехватке
  места или ошибке подготовки сведения открываются автоматически, установка блокируется.
- Загрузка занимает нижнюю полосу: видны этап, объём, скорость и доступные действия.
  Пауза и переход между экранами сохраняют состояние.
- Отдельный экран настроек, управляемое сохранение и восстановление видео сохранены.

Убраны белые карточки, отдельная верхняя полоса с названием, выдуманный знак L,
декоративная сетка и штриховка кнопки. Пользовательская иконка скопирована без изменения
из `GhUTmc5acAAvzFP.png`; логотип игры остаётся частью официального арта.

[Исходный план](plan.md), [первоначальный прототип](prototype.html) и снимки в
`revised/` относятся к предыдущим итерациям. Для текущего вида используйте
снимки в `home-fix/`; `implemented/` содержит проверки на тестовых данных.

Браузерные проверки моделируют состояние игры и команды Tauri; установки и

Для повторения автоматических проверок, при запущенном `npm run dev`:

```bash
node scripts/check-ui.cjs
UI_ARTWORK_PATH=/path/to/official-background.png node scripts/check-appearance.cjs
```

Можно указать `PLAYWRIGHT_MODULE` и `CHROMIUM_PATH` для внешней установки Playwright.

## Запуск

Из корня проекта, после сборки:

```bash
./src-tauri/target/release/llauncher
```

Перед запуском новой сборки полностью закройте старый экземпляр через трей:
приложение допускает только один запущенный экземпляр.

Сборка Linux без создания установочных пакетов:

```bash
npm run tauri -- build --no-bundle --config '{"build":{"beforeBuildCommand":"npm run build"}}'
```

## Что изменилось и почему

| Изменение | Польза |
| --- | --- |
| Одна основная кнопка на главной | Следующее действие определяется состоянием игры: установка, обновление, запуск или продолжение. |
| Папка, размер и свободное место перед установкой | Решение можно принять до начала загрузки. Неизвестный размер обозначается явно. |
| Этапы, объём, процент, скорость и оставшееся время | Прогресс виден без технических журналов. На паузе сохраняется загруженный объём. |
| Общее состояние операций в Rust | Переход в настройки не теряет загрузку. После перезапуска незавершённая операция доступна для продолжения. |
| Настройки на отдельном экране | Общие настройки, файлы, запуск, моды и диагностика доступны через постоянную навигацию. |
| Явное сохранение настроек | Несохранённые изменения видны; закрытие требует выбора. Автозапуск также применяется при сохранении. |
| Короткие строки модов | EFMI, папка, каталог, переключатели и статусы. Объяснения модов и аналогии удалены. |
| Дополнительные параметры раскрываются по запросу | Основные действия остаются на виду; редкие параметры доступны без перегрузки экрана. |
| Ошибки рядом с действием | Повтор доступен сразу, технические подробности раскрываются отдельно и копируются. |
| Фокус клавиатуры и модальные окна | Escape, возврат фокуса, переключение вкладок новостей стрелками и безопасный начальный фокус в подтверждениях. |

## Восстановление видео

Видимость и фокус проверяются через Tauri, с DOM-событиями в качестве резерва.
Проверка состояния окна раз в 2 секунды покрывает пропущенные события возврата
из трея. Пока окно скрыто, видео приостанавливается.

При показе окна воспроизведение запускается снова. Прерванный `play()` не удаляет
видео. Проверяется движение медиавремени и, при поддержке браузера, счётчика кадров.
После 4,5 секунды без движения выполняется пауза/повторный запуск, после 9 секунд —
перезагрузка потока с восстановлением позиции. Повторные ошибки используют
увеличивающийся интервал; во время восстановления остаётся статичный фон.
Системное предпочтение уменьшенного движения отключает видео.

Это защита от нескольких наблюдаемых состояний зависания. Исходный сбой на
конкретной связке GPU/WebKitGTK/GStreamer пользователя пока не воспроизведён.
